# 0002 — 本机与 Worktree 的分支语义、chip 顺序与创建入口

日期: 2026-11-02
状态: 已接受

## 背景

0001 决定了 chip 挂在 hero 工作区行、worktree 在「创建并进入」时创建。落地时还要把「分支」和「环境」拆成两个语义，并对照 Cursor：选 Worktree 不改本机检出，发送前再确认。dsh 0.2.0-rc.1 没有普通消息的发送前拦截（见 0001），因此不能做成「点发送才建 worktree」。同时，用户要求环境在左、分支在右，创建入口放在分支列表下面，而不是再开一层确认。

## 决策

**环境在左、分支在右。** 分支 chip 的含义随环境变化：本机表示当前检出；Worktree 表示即将创建的基线分支。选 Worktree 时自动打开分支面板。

**本机改检出，Worktree 不改。** 环境为本机时，改分支走 `git switch`（有未提交改动或该分支已被其他 worktree 占用则拒绝）。环境为 Worktree 时，本机 HEAD 不动，只记录创建基线；主仓库即使有未提交改动，仍允许创建 worktree。

**创建入口在分支列表下方。** 手动命名时名称框和「创建并进入」紧挨列表；自动短码时只留说明和按钮。名称框回车等同点击按钮。创建后注册 Workspace、打开其空白会话并带入草稿（流程同 0001）。

- 被否决：发送时创建（没有拦截点，Enter / Cmd+Enter 也拦不住）；省略「创建并进入」、只靠选名字就建（会在浏览分支时误建）；Worktree 下列已有功能分支并切过去（Worktree 只表示「基于某基线新建」）。
- 代价：用户比 Cursor 的「发送前询问」多点一次「创建并进入」。等上游提供 before-send 后再评估是否收回。

## 影响

- 正面：本机会话与 worktree 会话职责分开，主仓库检出不会被创建动作带跑；chip 从左到右是「在哪工作 → 基于哪条分支」。
- 负面：没有发送拦截，空白会话里先打字再决定环境时，草稿仍在本机会话，创建时再交接。
- 验证：本机 `git switch` 拒绝脏工作区与占用分支；Worktree 创建后主仓库仍停在原分支。
